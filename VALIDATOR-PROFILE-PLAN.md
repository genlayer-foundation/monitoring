## Goal

One page a validator opens to answer, top to bottom:

1. **Am I OK?** — one verdict, and the list of what is wrong.
2. **What do I do about it?** — the node's own diagnosis, with the action.
3. **Am I earning?** — stake, rewards, slashing, per epoch.
4. **Am I doing my job?** — duties, votes, leader turns, idleness.
5. **Why did it go wrong?** — strikes, quarantine, the transactions that caused them.
6. **Is my machine healthy?** — sync, RPC, GenVM, resources, logs.

Today's board answers only part of 1 and 6. It has no money, no work, no
"why", and its log panels are broken (see Fixes).

Worked example the page must explain on its own: `genlayer-foundation-bradbury-1`
(`0xB0dA…3342`), on 2026-10-27 — 3 idleness strikes in epoch 6 → quarantined
at block 184440 until epoch 8, slashed 774.76 GEN (ep 4) and 901.86 GEN (ep 5),
a further 300 bps slash pending for ep 6, 0 rewards in ep 7, 0 validator
commits in the last 6h. Every one of those facts is readable today (sources below).

The explorer indexer is new: `deckard-testnet-agent/docs/architecture/data-sources.md`

Rule: **the explorer for history and lists, the chain for the few live facts
that decide status, Prometheus/Loki for the node.** The chain stays the
authority for status (a fact the explorer and chain disagree on shows the chain).

## Layout

Each row names its panels and the exact source. "E:" = explorer route,
"C:" = chain call, "P:" = PromQL, "L:" = LogQL.

### Row 1 — Verdict (always open)

| Panel | Source |
|---|---|
| **Health** — big stat, portal colour + label | portal `health.color/label` (same jq as Validator Status) |
| **What's wrong** — table, one row per finding: severity, type, detail | portal `health.findings[]` |
| **Participation** — active / quarantined until epoch N / no longer participating | C: `validatorBanned` `0x090d60bd` + `epoch()`; fallback E: `/address/{addr}` `status`, `banned_until_epoch` |
| **Strikes this epoch** — `x / 3` | C: Idleness `strikesPerEpoch(addr, epoch)` `0xd8a4f66f`, `strikesMax` `0x85b835b2`; or E: `strikes_current/strikes_max` |
| **Primed for next epoch** | E: `is_primed_next_epoch` (C: `validatorView` ePrimed) |
| **Pending slash** — bps due next prime | C: Slash `slashPerValidator(addr, epoch-1)` `0xb81aa850` |
| Version (+ Up to date / Behind), Synced, Metrics ON/OFF, Logs ON/OFF | existing panels 20/21/3/18/19 |

### Row 2 — Node's own diagnosis ("what to do")

The node already diagnoses itself across 12 conditions; no board uses it.

| Panel | Source |
|---|---|
| **Conditions** — table: condition, state (coloured), last reason, last success | P: `genlayer_node_operator_condition_state{node="$node"} == 1`, `…_occurrences_total`, `…_last_success_timestamp_seconds` |
| **Condition timeline** — state-timeline, one lane per condition | P: same, mapped healthy→green … unavailable→red |
| **Attention log** — the node's "requires attention" lines: condition, reason, impact, **action** | L: `{job="genlayer-node", validator_name="$validator_name"} \| json \| __error__="" \| message="operator condition requires attention"` |

### Row 3 — Money

| Panel | Source |
|---|---|
| Self stake, delegated stake, delegators, pending deposit/withdrawal | C: `validatorView` `0xb83f5b39` (one call) or E: `/address/{addr}` |
| **Stake per epoch** — line | E: `/epochs/{n}/validators` `self_stake` (see "History" below) |
| **Rewards vs slashing per epoch** — bars, green up / red down | E: same route: `validator_rewards`, `delegator_rewards`, `fee_rewards`, `validator_slashing`, `fee_penalties` |
| Rewards earned (node's counter) — running total | P: `genlayer_node_fees_earned_wei_total{type="validator_rewards"}` |
| Gas spent per duty | P: `sum by (method)(increase(genlayer_node_gas_spent_wei_total[$__range]))` |

### Row 4 — Work done

| Panel | Source |
|---|---|
| **Performance (7d)** — leader turns, rotations %, minority votes %, idle %, successful appeals | E: `/address/{addr}` `*_7d` fields |
| **Duties per hour** — leader proposed / revealed, validator commit / reveal, activations | P: `increase(genlayer_node_{leader_proposed,leader_revealed,validator_commit,validator_reveal,transactions_activated}_total[1h])` |
| **Submit outcomes** — success / failed / reverted per method | P: `genlayer_node_consensus_submit_total{method,outcome}` |
| **Vote breakdown** — majority / minority / timeout / idle | E: participations `outcome`, or C: `VoteRevealed` voteType (topic2 = validator) |
| **Recent transactions** — table: time, round, role, outcome (coloured), link to scan | E: `/transactions/participations?address=&page_size=100` |

### Row 5 — Why it went wrong (strikes, quarantine)

| Panel | Source |
|---|---|
| **Idle transactions** — table with scan links | E: participations `role_filter=idle` |
| **Status per epoch** — active / quarantined strip | E: `/epochs/{n}/validators` `status` |
| **Idle / replaced events** from the node | L: `message=~"Validator\\(s\\) idle.*\|Leader is idle.*"` filtered to this node in `idleValidators` |
| Quarantine record — epoch, until, evidence tx | C: `ValidatorBannedIdleness` logs (non-indexed: fetch topic, filter in jq) — or reuse Deckard's investigation |

### Row 6 — Sync & connectivity (collapsed)

Blocks behind + latest vs synced (existing), **health state** timeline
(`genlayer_node_health_state`: 0 Synced / 1 Degraded / 2 CatchingUp / 3 HopelesslyBehind),
sync ETA (L: "Sync progress" `unwrap eta`), **RPC p50/p95 by method**
(`genlayer_rollup_rpc_request_duration_seconds_bucket`), **RPC errors by fault**
(provider vs blockchain), websocket reconnects, nonce manager (stuck / dropped /
gap / desync).

### Row 7 — GenVM & LLM (collapsed)

Executions per minute, **average execution time**
(`rate(_genvm_execution_time_seconds_total) / rate(_genvm_executions_total)`),
permits, GenVM internal errors / timeouts (L). LLM and web calls per execution
exist only inside the "genvm finished" log line (`genvm_log` metrics entry) —
**no provider/model metric exists anywhere**; ask Labs for one.

### Row 8 — Machine (collapsed)

CPU and memory **per component** (node, genvm-llm, genvm-web, webdriver),
disk bytes per directory + disk %, node network I/O, uptime, restarts.

### Row 9 — Logs (collapsed)

Error and warning **rate** over time, top recurring messages, recent errors,
recent warnings — all with the fixed selector (see Fixes).

## History — the one decision that needs infra

Per-epoch stake / rewards / slashing / status live in E: `/epochs/{n}/validators`,
**one call per epoch** (7 epochs so far, ~20 KB each, no address filter).
Infinity cannot loop over epochs. Options:

| Option | Effort | Pros | Cons |
|---|---|---|---|
| **A. Ask the explorer team for `/validators/{addr}/epochs`** (recommended) | an ask + one panel | one call, cached indexer, scales | waits on another team |
| B. Infinity, N fixed targets (epoch 1…N) + merge | hours | works today | edit the board every epoch; grows unbounded |
| C. Small exporter → Prometheus (`genlayer_validator_stake_wei{node}`, `_epoch_reward_wei`, `_slash_wei`, `_strikes`, `_quarantined_until_epoch`) | 1–2 days + a place to run it | native time series, alerts, survives RPC limits | new service to own |
| D. Infinity full-range `eth_getLogs` on Staking `ValidatorPrime` / `ValidatorSlash` | hours | chain-authoritative, exact to the wei | rate-limited, response grows weekly, 504 on wide filters |

Recommendation: **A, with B as a stopgap** (cheap now while there are 7 epochs).

## Who can open it — the second decision

Validators cannot open this board today: it needs a Grafana login, and
**public dashboards do not interpolate variables**, so one public board cannot
switch validator.

| Option | Pros | Cons |
|---|---|---|
| **Generated public board per validator** (recommended), like `build_public_validator_status.py`, with the node hard-coded; the portal / Deckard links each validator to theirs | no logins; per-validator URL | ~50 boards to regenerate on every change; Infinity URL/body vars must be pre-filled |
| Grafana viewer seats for validators | one board | per-seat cost, account admin, they see every board |
| Keep internal; Deckard quotes it | nothing to build | validators still can't "open this" |

Privacy rule for any public variant: **no raw GenVM logs** — "answer from
module" lines carry full LLM prompts and responses; Row 7/9 log panels must
filter them out or stay internal.

## Fixes found along the way (do in the first PR)

1. **Error / warning panels (13, 14, 15) always return nothing**: they put
   `network="$network"` in the stream selector, but node log streams carry no
   `network` label. Move it after `| json` and add `| __error__=""`.
2. Logs panels filter by `validator_name`; prefer `| json | node=~"(?i)$node"`
   (validator_name is not unique).
3. Never graph webdriver network counters (stuck at uint64 max).
4. Lazy counters (`consensus_revert_total`, `rpc_circuit_*`, …) need `or vector(0)`.
5. Always filter `network` on Prometheus: stale rc.1 series without it exist.
6. The profile can only select nodes that push metrics — add the roster's
   non-reporting validators to the `$validator_name` / `$node` choices
   (Infinity variable), since those are exactly the ones in trouble.
